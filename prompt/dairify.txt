## 🎯 Project Overview

**Project Name:** Dairify  
**Type:** Complete Dairy Management System and can kept the record of shop (Offline-First)  
**Target Users:** Dairy shop owners who collect milk from farmers and sell cattle products  
**Core Value:** Works seamlessly offline with automatic cloud sync when internet is available

---

## 🏗️ Technical Architecture

### **Tech Stack**
- **Frontend (App + Web):** Flutter (cross-platform)
- **Local Database:** Hive (offline storage for products, sales, stock, transactions)
- **Backend:** Laravel (MVC architecture)
- **Cloud Database:** PostgreSQL (official records, multi-device sync)
- **Architecture Pattern:** MVC (Model-View-Controller)

### **Offline-First Strategy**
- All operations save immediately to Hive local database
- Auto-sync to Laravel backend when internet is available
- Manual "Sync Now" button for forced synchronization
- Conflict resolution: Last-write-wins with timestamp tracking
- Local backup creation (daily/weekly)
- No data loss guarantee

## 📦 Core Modules & Features

### **1. Farmer Management Module**

**Purpose:** Unique identification and comprehensive farmer profile management

**Data Structure:**
```
Farmer {
  id: String (auto-generated: F001, F002, F003...)
  name: String
  village: String
  address: String (optional)
  phone: String (optional)
  milkType: Enum [Cow, Buffalo, Both]
  photo: String (path, optional)
  runningBalance: Decimal (calculated)
  createdAt: DateTime
  updatedAt: DateTime
  isActive: Boolean
}
```

**Features:**
- Auto-generate unique Farmer ID with prefix "F"
- Search/filter by ID, name, village, phone
- View running balance at a glance
- Deactivate farmer (soft delete)
- Photo capture/upload option
- Balance history visualization

---

### **2. Milk Collection System**

**Purpose:** Record daily milk collection with quality parameters and automatic payment calculation

**Data Structure:**
```
MilkCollection {
  id: String
  farmerId: String (FK)
  date: Date
  shift: Enum [Morning, Evening]
  quantity: Decimal (liters)
  fat: Decimal (percentage)
  snf: Decimal (percentage)
  ratePerLiter: Decimal (auto-calculated from rate chart)
  totalAmount: Decimal (auto-calculated)
  collectorId: String (user who recorded)
  isSynced: Boolean
  createdAt: DateTime
}
```

**Features:**
- Quick entry form: Farmer ID → Quantity → FAT → SNF → Auto-calculate
- Rate chart setup based on FAT/SNF ranges
- Shift-based collection (Morning/Evening)
- Duplicate entry prevention (same farmer, same shift, same date)
- Print/share collection slip
- Mark spoiled/rejected milk (deduct from total)
- Real-time totals: liters collected, total payable
- Collection summary by date/shift/farmer/village

**Rate Chart Logic:**
```
Rate = Base Rate + (FAT Bonus) + (SNF Bonus)
Example: ₹30 base + (6.0% FAT × ₹2) + (8.5% SNF × ₹1) = ₹42.5/liter
```

---

### **3. Advance & Credit (Audharo) System**

**Purpose:** Manage bidirectional money flow between shopkeeper and farmers

**Data Structure:**
```
Transaction {
  id: String
  farmerId: String (FK)
  type: Enum [MilkPayment, Advance, Credit, ProductPurchase, Settlement]
  amount: Decimal
  description: String
  date: Date
  runningBalance: Decimal (after this transaction)
  isSynced: Boolean
  createdAt: DateTime
}
```

**Transaction Types:**
1. **Milk Payment (+):** Auto-created from milk collection
2. **Advance (+):** Farmer gives money in advance
3. **Credit (-):** Farmer takes money/goods on credit
4. **Product Purchase (-):** Farmer buys cattle products
5. **Settlement (-):** Shopkeeper pays farmer (balance clearance)

**Auto-Adjustment Logic:**
```
New Milk Collection:
1. Calculate milk amount
2. Check if farmer has credit balance
3. Auto-deduct credit from milk payment
4. Update running balance
5. Show: "Milk: ₹800 - Credit: ₹100 = Net: ₹700"
```

**Features:**
- Add advance payment (farmer → shopkeeper)
- Record credit given (shopkeeper → farmer)
- Auto-deduct credit from milk payments
- Settlement workflow with payment mode (Cash/UPI/Bank)
- Transaction history with filters
- Outstanding credit report

## 🔄 Sync Strategy

### **Local-First Architecture**

**Write Flow:**
```
User Action → Validate → Save to Hive → Update UI → Queue for Sync
```

**Sync Flow:**
```
1. Check internet connectivity
2. If online:
   - Fetch unsynced records from Hive
   - Send to Laravel API endpoint
   - On success: Mark as synced in Hive
   - On failure: Retry with exponential backoff
3. Download server updates
4. Resolve conflicts (last-write-wins with timestamp)
```

**Conflict Resolution:**
- Timestamp-based: Most recent update wins
- Server timestamp is authoritative
- Log conflicts for admin review

**Sync Indicators:**
- Green dot: All synced
- Yellow dot: Syncing in progress
- Red dot: Sync errors (show count)
- "Last synced: 5 minutes ago"
