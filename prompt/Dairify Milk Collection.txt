# Dairify - Milk Collection Smart Auto-Fill Feature
## Context Engineering Prompt for Development

---

## 🎯 Feature Requirement

**Feature:** Smart Auto-Fill for Milk Collection Entry Form  
**Goal:** Reduce milk collection entry time from 30 seconds to under 10 seconds per farmer by automatically filling previous values

---

## ⌨️ Auto-Fill Trigger Behavior

### **Keyboard Triggers**
- **Enter Key** or **Tab Key**: Automatically fill field with previous value if field is empty, then move to next field
- **Manual Entry**: User can type to override any auto-filled value
- **Field Selection**: Auto-filled values are highlighted for easy replacement

---

## 📋 Field-by-Field Auto-Fill Specification

### **1. Date Field**
```
Behavior: Auto-detect from device date (always)
Format: DD-MM-YYYY or based on device locale
Source: Device system date
Editable: Yes (for backdated entries)
```

### **2. Time Field**
```
Behavior: Auto-detect from device time (always)
Format: HH:MM AM/PM or 24-hour based on device settings
Source: Device system time
Editable: Yes (for backdated entries)
```

### **3. Shift Field**
```
Behavior: Auto-select based on current time
Logic:
  - 05:00 AM to 11:59 AM → Morning
  - 12:00 PM to 04:59 AM → Evening
Source: Device time
Editable: Yes (manual override allowed)
```

### **4. Quantity (Liters) Field**
```
Trigger: User presses Enter/Tab on empty field
Action: 
  - Fetch last quantity value for selected farmer
  - Auto-fill the field
  - Highlight text (select all)
  - Move focus to next field
Source: Last milk collection entry of same farmer_id
Editable: Yes (user can type new value)
Query: SELECT quantity FROM milk_collections 
       WHERE farmer_id = ? ORDER BY created_at DESC LIMIT 1
```

### **5. FAT (%) Field**
```
Trigger: User presses Enter/Tab on empty field
Action: 
  - Fetch last FAT value for selected farmer
  - Auto-fill the field
  - Highlight text (select all)
  - Trigger rate recalculation
  - Move focus to next field
Source: Last milk collection entry of same farmer_id
Editable: Yes (user can type new value)
Query: SELECT fat FROM milk_collections 
       WHERE farmer_id = ? ORDER BY created_at DESC LIMIT 1
```

### **6. SNF (%) Field**
```
Trigger: User presses Enter/Tab on empty field
Action: 
  - Fetch last SNF value for selected farmer
  - Auto-fill the field
  - Highlight text (select all)
  - Trigger rate recalculation
  - Move focus to next field
Source: Last milk collection entry of same farmer_id
Editable: Yes (user can type new value)
Query: SELECT snf FROM milk_collections 
       WHERE farmer_id = ? ORDER BY created_at DESC LIMIT 1
```

### **7. Rate Field (Auto-Calculated)**
```
Behavior: Always auto-calculated (not from previous entry)
Trigger: When FAT or SNF values are entered/changed
Calculation: Rate = Base Rate + (FAT Bonus) + (SNF Bonus)
Display: Show as calculated with info icon
Editable: Only by Admin role (Collector role: read-only)
Example: Base ₹30 + (FAT 6.2% × ₹2) + (SNF 8.4% × ₹1) = ₹32.80
```

### **8. Amount Field**
```
Trigger Option 1: User presses Enter/Tab on empty field
Action:
  - Auto-calculate: Quantity × Rate
  - Fill the amount field
  - Highlight value
  - Move to Save button

Trigger Option 2: Quantity or Rate changes
Action:
  - If amount field is empty OR was previously auto-calculated
  - Recalculate: Quantity × Rate
  - Update amount field

Manual Entry Override:
  - User can manually type amount
  - System shows warning: "Manual amount differs from calculated"
  - Display: Calculated: ₹X.XX | Entered: ₹Y.YY | Diff: ±₹Z.ZZ
  - Allow save (admin override scenario)

Calculation: Amount = Quantity × Rate
Display: Show calculation hint (e.g., "18.5 L × ₹32.80")
Editable: Yes (with warning if differs from calculated)
```

## 💻 Technical Implementation Guidelines

### **Data Fetching Logic**
```
On Farmer Selection:
1. Load last milk collection entry for that farmer
2. Store in memory for quick access
3. Display in preview card
4. Use for auto-fill when fields lose focus

Query Structure:
{
  SELECT quantity, fat, snf, rate, amount, date, shift
  FROM milk_collections
  WHERE farmer_id = '{selected_farmer_id}'
  ORDER BY created_at DESC
  LIMIT 1
}
```

### **Field Event Handling**
```
TextField Properties:
- onSubmitted: Triggered on Enter key
- onEditingComplete: Triggered on Tab key
- onTap: Select all if auto-filled
- onChanged: Clear auto-fill flag if user types

Focus Management:
- FocusNode for each field
- Auto-advance focus on Enter/Tab
- Highlight text when auto-filled
- Clear selection when user starts typing
```

### **Calculation Triggers**
```
Rate Calculation:
- Triggered when: FAT changes OR SNF changes
- Method: Fetch from rate chart based on FAT/SNF values
- Update: Rate field (read-only display)

Amount Calculation:
- Triggered when: Quantity changes OR Rate changes
- Method: Quantity × Rate
- Update: Amount field (if empty or previously auto-calculated)
- Flag: Track if amount is auto-calculated vs manual
```

### **State Management**
```
Track for each field:
- isAutoFilled: Boolean (true if value came from last entry)
- isCalculated: Boolean (true if value is calculated)
- isManuallyEdited: Boolean (true if user typed a value)
- lastEntryData: Object (cached previous entry data)
```

# Dairify - Duplicate Entry Prevention System
## Context Engineering Prompt for Development

---

## 🎯 Feature Requirement

**Feature:** Duplicate Entry Detection & Confirmation System  
**Goal:** Prevent accidental duplicate milk collection entries for the same farmer on the same date and shift  
**Method:** Show popup confirmation when duplicate entry is detected

---

## 🔍 Duplicate Entry Detection Logic

### **What Constitutes a Duplicate Entry?**

```
A duplicate entry is detected when ALL of the following match:

1. Same Farmer ID
2. Same Date
3. Same Shift (Morning or Evening)

Example Duplicate Scenario:
┌─────────────────────────────────────────────┐
│ Existing Entry in Database:                 │
│ Farmer: F001 (Ramesh Patel)                │
│ Date: 28-10-2025                            │
│ Shift: Morning                              │
│ Quantity: 18.5 L                            │
├─────────────────────────────────────────────┤
│ New Entry Attempt:                          │
│ Farmer: F001 (Ramesh Patel)                │
│ Date: 28-10-2025                            │
│ Shift: Morning                              │
│ Quantity: 20.0 L                            │
└─────────────────────────────────────────────┘
        ↓
   🚨 DUPLICATE DETECTED!
```

---

## ⚠️ When to Check for Duplicates

### **Trigger Points**

```
Check #1: On Farmer Selection + Date/Shift Change
├─ User selects farmer from dropdown
├─ Date and shift fields are auto-filled/changed
├─ System immediately checks for existing entry
└─ Show warning badge if duplicate exists

Check #2: Before Save Button Click
├─ User clicks "Save Entry" button
├─ System performs final duplicate check
├─ If duplicate found: Show confirmation popup
└─ If no duplicate: Save directly

Check #3: On Shift Toggle (if date is same)
├─ User changes shift from Morning to Evening (or vice versa)
├─ System checks for existing entry with new shift
└─ Show warning badge if duplicate exists
```

## 🔄 User Action Flow & Options

### **Option 1: Cancel**

```
User Action: Clicks "Cancel" button
System Response:
├─ Close popup
├─ Return to form (no changes)
├─ Keep form data intact
├─ User can modify and try again
└─ No database changes
```

### **Option 2: Replace Existing Entry**

```
User Action: Clicks "Replace Existing" button
System Response:
├─ Show confirmation sub-dialog:
│   ┌─────────────────────────────────────┐
│   │ ⚠️ Confirm Replace                  │
│   │                                     │
│   │ This will delete the old entry     │
│   │ and save the new one.              │
│   │                                     │
│   │ Old entry will be moved to         │
│   │ "Deleted Entries" log.             │
│   │                                     │
│   │ [Go Back] [✅ Yes, Replace]        │
│   └─────────────────────────────────────┘
├─ If confirmed:
│   ├─ Soft delete existing entry (mark as deleted)
│   ├─ Save deletion log with reason: "Replaced"
│   ├─ Save new entry
│   ├─ Update farmer ledger (adjust balances)
│   ├─ Show success message: "Entry replaced successfully"
│   └─ Clear form and prepare for next entry
└─ If not confirmed: Return to main popup
```

### **Option 3: Add as New Entry (Force Duplicate)**

```
User Action: Clicks "Add as New Entry" button
System Response:
├─ Show confirmation sub-dialog:
│   ┌─────────────────────────────────────┐
│   │ ⚠️ Confirm Duplicate Entry          │
│   │                                     │
│   │ This will create a SECOND entry    │
│   │ for the same farmer, date & shift. │
│   │                                     │
│   │ Reason: ________________           │
│   │ (Optional: "Second collection")    │
│   │                                     │
│   │ [Go Back] [✅ Yes, Add]            │
│   └─────────────────────────────────────┘
├─ If confirmed:
│   ├─ Flag entry as "intentional_duplicate"
│   ├─ Save duplicate reason in entry
│   ├─ Save new entry (both entries exist)
│   ├─ Update farmer ledger (add both amounts)
│   ├─ Show success message: "Duplicate entry saved"
│   └─ Clear form and prepare for next entry
└─ If not confirmed: Return to main popup

Use Cases for Legitimate Duplicates:
- Farmer brings milk twice in same shift
- Correction entry (different quality detected later)
- Split delivery (morning collection in two batches)
- Multiple cattle owners using same ID
```

### **Option 4: Edit Existing Entry**

```
User Action: Clicks "Edit Existing" button (from warning badge)
System Response:
├─ Load existing entry data into form
├─ Change mode to "Edit" (not "New")
├─ Pre-fill all fields with existing values
├─ Change Save button to "Update Entry"
├─ Allow modifications
├─ On save:
│   ├─ Update existing entry (no duplicate created)
│   ├─ Log modification with timestamp
│   ├─ Update farmer ledger (adjust if amount changed)
│   └─ Show success: "Entry updated successfully"
└─ Close form
```

## 🔍 Duplicate Detection Query

### **Check for Existing Entry**

```sql
-- Hive/Local Query (Pseudo-code)
SELECT * FROM milk_collections 
WHERE farmer_id = '{selected_farmer_id}' 
  AND date = '{selected_date}' 
  AND shift = '{selected_shift}'
  AND is_deleted = false
ORDER BY created_at DESC
LIMIT 1

-- Laravel/PostgreSQL Query
DB::table('milk_collections')
  ->where('farmer_id', $farmerId)
  ->where('date', $date)
  ->where('shift', $shift)
  ->where('is_deleted', false)
  ->orderBy('created_at', 'desc')
  ->first();
```

### **Check Timing (Performance)**

```
When to Execute:
✅ On farmer selection change (after 500ms debounce)
✅ On date change (after 300ms debounce)
✅ On shift change (immediate)
✅ On save button click (immediate, blocking)

Performance Requirements:
- Query execution: < 50ms
- Popup display: < 100ms after detection
- No UI freeze/lag during check
```
